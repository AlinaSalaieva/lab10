# Лабораторна робота №10 — варіант 21

Тема: застосування поведінкових патернів проєктування. Предметна область: GPS-моніторинг. Проєкт розширює ЛР8: C++20, SQLite, sqlite_orm, Repository, сутності GpsObject та TrackPoint (1:N).

- State: Отримана → Перевірена → Опрацьована; з отриманої або перевіреної дозволено перейти до некоректної. Кінцеві стани не допускають переходів. Поточний стан та історія переходів зберігаються атомарно в SQLite.
- Strategy: середня швидкість `v = 3600*d/t` (км/год); нормована оцінка `v/vmax`; оцінка з коефіцієнтом допустимого відхилення `v/(vmax*k)`. Відстань у км, час у секундах, допустима швидкість у км/год. У демонстрації `k = 1.1` (10% допуску). Методичка не задає конкретної формули для третьої стратегії або величини коефіцієнта; це обрана інтерпретація. Подія відхилення виникає, якщо середня швидкість перевищує допустиму незалежно від обраного способу оцінювання.
- Observer: події отримання точки треку та відхилення швидкості; підписники TrackLogger і ObjectMonitor. Журнал і монітор демонструють реакції в консолі.
- Facade: GpsMonitoringFacade надає спільний інтерфейс отримання точки, зміни стану, оцінки швидкості та керування підписками.

## Збирання у Windows

Відкрити папку проєкту в VS Code, термінал PowerShell. Потрібні CMake, Visual Studio з компонентами C++ та vcpkg. Вказати фактичний шлях до вже встановленого vcpkg (приклад):

```powershell
$env:VCPKG_ROOT = "C:\vcpkg"
cmake --preset windows-vcpkg
cmake --build build --config Debug
```

Початковий preset із ЛР8 використовує Visual Studio 18 2026. Для іншої версії Visual Studio замінити лише значення generator у CMakePresets.json відповідно до `cmake --help`.

## Запуск

```powershell
.\build\Debug\GPSMonitorORM_V21.exe state
.\build\Debug\GPSMonitorORM_V21.exe strategy
.\build\Debug\GPSMonitorORM_V21.exe observer
.\build\Debug\GPSMonitorORM_V21.exe facade
.\build\Debug\pattern_tests.exe
.\build\Debug\integration_tests.exe
ctest --test-dir build -C Debug --output-on-failure
```

Усі демонстрації: `GPSMonitorORM_V21.exe all`. Вибір одного алгоритму: `GPSMonitorORM_V21.exe strategy 1` (або `2`, `3`).

Кожний демонстраційний режим відтворює власну тестову БД `gps_lab10_<режим>.db` із початковими 5 об'єктами і 15 точками. Після завершення БД залишається на диску. Повторний запуск того самого режиму відтворює її заново; не використовується БД ЛР8. Приклади відстані, часу і ліміту задаються як тестові вхідні параметри, а не обчислюються із координат.

Модульні тести перевіряють State, Strategy і Observer. Інтеграційні тести — Facade, ORM, збереження історії, COMMIT і ROLLBACK при примусовій помилці INSERT, повторне відкриття БД. Тестова БД відокремлена від демонстраційних.
